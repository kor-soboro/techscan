## 🤖 Agent Tools & Frameworks (메인)

### 1. [OpenHuman](https://github.com/tinyhumansai/openhuman) — Personal AI Agent with Local Brain
- **무엇**: 오픈소스 데스크톱 AI 에이전트. 20분마다 사용자 도구·파일·앱을 스캔해 Markdown 파일로 로컬 저장하는 "항상-켜져 있는 개인 메모리"가 핵심. 클라우드 의존 없이 컨텍스트 유지
- **적용 포인트**: Claude Code / Cursor 같은 코딩 에이전트에 사용자 선호·프로젝트 맥락을 자동 주입하는 파이프라인 구성 가능; 로컬 Markdown 메모리라 직접 편집·검토 가능
- **출처**: [TechTimes (2026-05-16)](https://www.techtimes.com/articles/316731/20260516/agent-that-reads-you-first-openhuman-tops-github-trending-inverting-playbook.htm) · [AIToolly (2026-05-17)](https://aitoolly.com/ai-news/article/2026-05-17-openhuman-project-debuts-on-github-a-new-vision-for-private-and-simple-personal-ai-superintelligence)

### 2. [oh-my-pi](https://github.com/can1357/oh-my-pi) — Terminal AI Coding Agent
- **무엇**: `can1357` 개발. "해시앵커 편집(hash-anchored edits)"으로 AI 코드 수정 정확도 향상. LSP(언어 서버 프로토콜) 연동, Python 스크립팅, 인라인 브라우저, 서브에이전트 지원을 하나의 터미널 하네스에 통합
- **적용 포인트**: 기존 Claude Code·Aider보다 정밀한 파일 수정이 필요한 대규모 리팩터링이나 레포 전체 에이전트 작업에 적합. LSP로 심볼 정보까지 참조
- **출처**: [AIToolly (2026-05-22)](https://aitoolly.com/ai-news/article/2026-05-22-exploring-oh-my-pi-a-terminal-based-ai-programming-agent-featuring-hash-anchored-editing-and-lsp-int)

### 3. [Microsoft Conductor](https://github.com/microsoft/conductor) — Deterministic Multi-Agent Orchestration
- **무엇**: Microsoft 오픈소스(MIT). YAML로 에이전트·프롬프트·라우팅 논리를 선언, Jinja2 조건 평가로 결정론적 라우팅 — **LLM이 오케스트레이션 토큰을 소모하지 않음**. GitHub Copilot SDK + Anthropic Claude 둘 다 지원, 병렬 그룹 및 동적 for-each 배치 실행 내장
- **적용 포인트**: 구조가 알려진 파이프라인(분류 → 조사 → 종합)에서 비용·지연·불확실성을 줄이는 IaC 스타일 에이전트 설계에 최적. `--web` 플래그로 실시간 DAG 대시보드 제공
- **출처**: [Microsoft Open Source Blog (2026-05-14)](https://opensource.microsoft.com/blog/2026/05/14/conductor-deterministic-orchestration-for-multi-agent-ai-workflows/) · [GitHub](https://github.com/microsoft/conductor)

### 4. [ComposioHQ / agent-orchestrator](https://github.com/ComposioHQ/agent-orchestrator) — Parallel Coding Agent Fleet
- **무엇**: 코딩 에이전트를 병렬로 실행하는 오케스트레이터. 각 에이전트가 독립 git worktree·브랜치·PR을 가짐. CI 실패 자동 수정, 리뷰어 댓글 자동 처리, 병합 충돌 자율 해결 — 사람 개입은 판단이 필요한 시점만
- **적용 포인트**: 큰 태스크를 서브태스크로 분해해 병렬 처리할 때 인간 감독 비용 최소화. `localhost:3000` 대시보드로 에이전트 플릿 모니터링 가능
- **출처**: [GitHub (ComposioHQ)](https://github.com/ComposioHQ/agent-orchestrator)

### 5. [Google Antigravity 2.0](https://techcrunch.com/2026/05/19/google-launches-antigravity-2-0-with-an-updated-desktop-app-and-cli-tool-at-io-2026/) — Agent-First Dev Platform
- **무엇**: Google I/O 2026에서 발표. Go로 재작성된 CLI, 리뉴얼 데스크톱 앱, Antigravity SDK 3종 구성. 서브에이전트 병렬 오케스트레이션, 스케줄 자동화, 크로스 플랫폼 터미널 샌드박싱·크리덴셜 마스킹·강화된 Git 정책 내장. Gemini CLI에서 Antigravity CLI로 공식 전환
- **적용 포인트**: Google AI Studio·Firebase·Android와 깊이 통합. Gemini 3.5 모델로 백킹된 에이전트를 자체 인프라에 배포하는 SDK 경로 제공
- **출처**: [TechCrunch (2026-05-19)](https://techcrunch.com/2026/05/19/google-launches-antigravity-2-0-with-an-updated-desktop-app-and-cli-tool-at-io-2026/) · [Google Developers Blog](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/)

### 6. [n8n](https://docs.n8n.io/release-notes/) — AI Agent Node 업데이트
- **무엇**: 5월 업데이트에서 AI Agent Node의 MCP 툴 이름 추출 수정, 도구 기본값 표현식 지원, 대화형 워크플로에서 Human-in-the-loop(HITL) 강화. `intermediateSteps` messageLog 직렬화도 개선
- **적용 포인트**: 비주얼 빌더 + MCP 연동 원하는 팀에서 사람이 특정 도구 실행 전 승인하는 감사 파이프라인 구축에 유리
- **출처**: [n8n Release Notes](https://docs.n8n.io/release-notes/) · [Releasebot](https://releasebot.io/updates/n8n)

### 7. [WebMCP (Web Standard Proposal)](https://blog.google/innovation-and-ai/technology/developers-tools/google-io-2026-developer-highlights/) — 브라우저용 MCP 표준 초안

## 🔬 Research & Techniques

- [[2605.18747] Code as Agent Harness](https://arxiv.org/abs/2605.18747) — "코드가 곧 에이전트 하네스다" 패러다임 제안; LLM 코드 생성 능력을 에이전트 오케스트레이션 레이어 자체로 활용하는 이론적 프레임워크 (2026-05-18)
- [[2605.10481] Safe Multi-Agent Behavior: Constraint Drift](https://arxiv.org/abs/2605.10481) — LLM 기반 멀티에이전트 시스템에서 실행 중 안전 제약이 표류하는 "Constraint Drift" 문제 정의, Constraint State Governance 연구 패러다임 제안 (2026-05-11)
- [[2605.11453] Predictive Maps of Multi-Agent Reasoning](https://arxiv.org/abs/2605.11453) — 멀티에이전트 LLM 통신 그래프를 successor representation 기반으로 진단; 스펙트럼 지표로 3가지 실패 모드 연결 (2026-05-12)
- [[2605.13496] MARLIN: Multi-Agent RL for Sustainable LLM Inference](https://arxiv.org/abs/2605.13496) — 게임이론적 RL로 TTFT 18% ↓, 탄소 배출 33% ↓, 수자원 43% ↓, 에너지 11% ↓ 달성하는 클라우드 LLM 추론 스케줄링 (2026-05-13)
- [Trust Over Fear: Motivation Framing in System Prompts](https://arxiv.org/pdf/2603.14373) — "PUA 프롬프팅(협박형 지시)"과 긍정 동기부여 프레이밍이 에이전트 디버깅 깊이에 미치는 영향 실험; 공포 기반이 반드시 유리하지 않음
