# Weekly AI Agent Tech Scan — 2026-05-25

- **Microsoft Conductor**(5/14)가 YAML 선언형 멀티에이전트 오케스트레이션을 오픈소스로 공개했다. 오케스트레이션 계층이 LLM 토큰을 전혀 소비하지 않는 설계로 주목받는다.

### 1. [Statewright](https://statewright.ai/) — 상태 머신 가드레일로 에이전트 신뢰성 강화

**무엇** AI 코딩 에이전트(Claude Code, Cursor, Codex 등)의 툴 접근 권한을 워크플로 단계별로 제한하는 Rust 엔진 기반 가드레일 시스템. MCP 및 hooks 방식으로 에이전트 하네스에 연결한다.

**쉬운 비유** 주방 요리 단계마다 꺼낼 수 있는 도구를 다르게 잠그는 것과 같다. 재료 손질 단계엔 칼만, 가열 단계엔 냄비만, 완성 단계엔 접시만 열린다. 에이전트가 생각(계획) 단계에서는 파일 편집 도구 자체에 접근할 수 없다.

| 라벨 | 값 |
|---|---|
| 인증 방식 | 로컬 Rust 엔진(오픈소스) / 관리형 클라우드(statewright.ai) 자체 백엔드 |
| 비용 | 오픈소스 엔진 무료(Apache 2.0, 일부 FSL-1.1-ALv2) / 관리형 클라우드 가격 미공개 |
| 주목할 가치 | 5개 SWE-bench 작업 서브셋 실험에서 제약 없이 2/10이던 로컬 모델이 제약 적용 후 10/10을 기록. LLM 없이 결정론적 Rust 엔진만으로 상태 전이를 처리해 오케스트레이션 비용이 없다. |

**유사 카테고리 비교**

| | Statewright | LangGraph | MCP Inspector |
|---|---|---|---|
| 신뢰성 접근 | 단계별 툴 잠금(하드 가드레일) | 그래프 분기·중단점 | 디버깅·시각화(가드레일 없음) |
| 오케스트레이션 방식 | 결정론적 Rust 엔진, 토큰 소비 없음 | LLM 라우팅(토큰 소비) | N/A |
| 에이전트 연동 | Claude Code, Cursor, Codex, Pi 플러그인 | 자체 에이전트 구현 필요 | Claude Desktop / MCP 서버 |
| 라이선스 | Apache 2.0 (일부 FSL) | MIT | MIT |

**5분 검증 액션** [GitHub 레포](https://github.com/statewright/statewright) README의 "How it works" 섹션과 [Hacker News 스레드](https://news.ycombinator.com/item?id=48108778)의 작성자 답변을 함께 읽으면 설계 의도와 한계를 10분 내로 파악할 수 있다.

### 2. [Microsoft Conductor](https://opensource.microsoft.com/blog/2026/05/14/conductor-deterministic-orchestration-for-multi-agent-ai-workflows/) — YAML 선언형 멀티에이전트 오케스트레이터

**무엇** 멀티에이전트 워크플로를 YAML 파일로 선언해두면 런타임에 결정론적으로 실행되는 오픈소스 CLI. 각 에이전트의 모델·프롬프트·입출력·라우팅을 파일에 미리 정의하며 오케스트레이션 레이어 자체는 LLM 토큰을 소비하지 않는다.

**쉬운 비유** 오케스트라 악보처럼, 어떤 연주자가 언제 무엇을 연주할지 미리 정확히 악보에 적어두면 그대로 연주된다. 지휘자(오케스트레이터)는 즉흥적으로 지시를 내리지 않는다.

| 라벨 | 값 |
|---|---|
| 인증 방식 | GitHub Copilot 계정 또는 Anthropic API key (BYOK) |
| 비용 | 무료(오픈소스, MIT) / LLM 호출 비용은 선택한 모델 제공자에 별도 부과 |
| 주목할 가치 | 오케스트레이션 구조가 YAML 파일로 버전 관리·diff·코드 리뷰 가능. 단일 워크플로 안에서 Claude Haiku(분류)·GPT-5.2(리서치·MCP 툴)·Claude Opus(복잡한 추론)를 혼합 지정할 수 있다. |

**유사 카테고리 비교**

| | Conductor | LangGraph | CrewAI |
|---|---|---|---|
| 워크플로 정의 | YAML 선언형 | Python 코드(그래프) | Python 코드(역할 기반) |
| 오케스트레이션 토큰 비용 | 없음 | 있음(LLM 라우팅) | 있음(LLM 역할 조율) |
| 동적 라우팅 | 지원 안 함(고정 토폴로지) | 지원 | 지원 |
| 라이선스 | MIT | MIT | MIT |

### 3. [Genkit Middleware](https://developers.googleblog.com/announcing-genkit-middleware-intercept-extend-and-harden-your-agentic-apps/) — 에이전트 생성 루프 전 계층 가로채기

**무엇** Google의 오픈소스 에이전트 프레임워크 Genkit에 추가된 미들웨어 시스템(5/14). `generate()` 호출과 툴 실행 루프를 generation·model·tool 세 계층에서 가로채 재시도, 모델 폴백, 민감 툴 승인 게이트, 스킬 파일 주입 등의 동작을 삽입할 수 있다.

**쉬운 비유** 공항 보안검색대처럼, 탑승객(AI 요청)이 출발 게이트에 닿기 전에 여러 창구를 순서대로 통과하면서 검사·처리된다. 창구(미들웨어)를 직접 설계해 원하는 규칙을 끼워 넣을 수 있다.

| 라벨 | 값 |
|---|---|
| 인증 방식 | Google AI API key 또는 Firebase 프로젝트 (BYOK 가능) |
| 비용 | 무료(오픈소스, Apache 2.0) / LLM 호출 비용 별도 |
| 주목할 가치 | TypeScript·Go·Dart 지원(Python 출시 예정). Dev UI에서 미들웨어 실행 흐름을 시각적으로 추적 가능. 사전 제작 미들웨어(재시도·폴백·승인 게이트·파일시스템 접근 제어·스킬 주입)가 포함돼 있어 직접 구현 없이 바로 적용 가능. |

| 언어 지원 | TS / Go / Dart (Python 예정) | TypeScript | Rust(엔진), 플러그인 다수 |

### 4. [mcp-recorder](https://github.com/devhelmhq/mcp-recorder) — MCP 서버 상호작용 기록·재생 테스트 도구

**무엇** MCP 서버와 클라이언트 사이의 전체 프로토콜 교환을 카세트 파일로 기록하고, 이후 서버 변경 시 동일 카세트로 회귀 검증을 실행하는 경량 프록시. CI 파이프라인에서 결정론적 MCP 서버 테스트가 가능해진다.

**쉬운 비유** 전화 통화를 녹음해뒀다가 나중에 "같은 질문에 같은 답변이 나오는지" 대조하는 것과 같다.

| 라벨 | 값 |
|---|---|
| 인증 방식 | MCP 서버 자체 인증 방식에 위임(프록시 역할, 별도 인증 없음) |
| 비용 | 오픈소스(라이선스 미확인) / pip install mcp-recorder |
| 주목할 가치 | MCP 서버를 직접 구축하거나 운영하는 팀이 즉시 적용 가능한 테스트 자동화 도구. 공개 데모 서버와 `scenarios.yml` 예시가 포함돼 별도 설정 없이 바로 실행해볼 수 있다. |

**5분 검증 액션** `pip install mcp-recorder` 설치 후 레포 동봉 `scenarios.yml`과 공개 데모 서버로 `mcp-recorder record` → `mcp-recorder verify` 흐름을 실행해 카세트 파일 구조를 확인한다.

- [GitHub — devhelmhq/mcp-recorder](https://github.com/devhelmhq/mcp-recorder)
