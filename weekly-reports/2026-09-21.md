**쉬운 비유** 여러 배달 기사(AI 도구)가 같은 건물(저장소)에 배달을 올 때, 각자 다른 규정집을 들고 다니는 대신 건물 입구에 붙어 있는 공통 안내문(AGENTS.md)을 모두 읽을 수 있게 된 것과 같다.

| 비용 | Claude Code 구독 포함 / API 토큰 비용 (LLM 호출 비용 별도) |

### 2. [Microsoft Agent Framework 1.19.0 — MCP 스테이트리스 마이그레이션](https://newreleases.io/project/github/microsoft/agent-framework/release/dotnet-1.19.0)

### 3. [arXiv 2609.20804 — 코딩 에이전트 하네스 설계 실증 연구](https://arxiv.org/abs/2609.20804)

**무엇** 고정된 실행 루프를 갖는 경량 코딩 하네스를 기반으로 planning·action space·context 관리 세 가지 요소를 독립 변수로 조정한 실험 논문이다. SWE-Bench Verified와 Terminal-Bench 2.1에서 4개 모델, 176개 설정을 평가했다. Hacker News에서 201점을 받으며 하네스 설계자 사이에 빠르게 확산됐다.

**쉬운 비유** 새 직원에게 도구를 어떻게 주느냐에 따라 업무 속도와 품질이 달라지는 것처럼, AI 에이전트에게 어떤 도구·정보·계획 지원을 어떻게 제공하느냐에 따라 성능과 비용이 크게 달라진다는 것을 176개 실험으로 확인한 연구다.

| 라벨 | 값 |
|---|---|
| 인증 방식 | 해당 없음 (논문) |
| 비용 | 무료 (오픈 액세스) |
| 주목할 가치 | 하네스 설계에 즉시 적용 가능한 구체적 가이드라인을 제시한다. ① bash 능숙 모델은 bash-only 인터페이스가 최저 비용을 달성, ② bash 미숙 모델은 predefined tools가 정확도를 보완, ③ planning은 약한 모델의 정확도 보조 수단이자 강한 모델의 비용 절감 수단, ④ context 관리는 실행 궤도를 늘리지만 에이전트 행동 자체를 크게 바꾸지는 않는다. 기존 벤치마크(SWE-Bench 등)가 결과를 측정하는 데 집중한 반면, 이 논문은 하네스 구성 요소 자체의 효과를 분리해 측정했다는 점이 차별점이다. |

**5분 검증 액션** [HuggingFace Papers 페이지](https://huggingface.co/papers/2609.20804)에서 초록 및 Table 1(결과 요약) 확인 → [alphaXiv 상세 페이지](https://www.alphaxiv.org/abs/2609.20804)에서 Section 4(Findings) 읽기
