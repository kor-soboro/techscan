### 1. [MCP Tasks Extension & MCP Apps](https://blog.modelcontextprotocol.io/)

**무엇** MCP 스펙 2026-07-28에서 확정되고 이번 MCP Dev Summit 토론토(Oct 5-6)에서 공식 발표된 두 가지 핵심 확장. Tasks Extension은 `tools/call`이 결과 대신 **태스크 핸들**을 반환하도록 바꿔 클라이언트가 `tasks/get` · `tasks/update` · `tasks/cancel`로 비동기 생명주기를 직접 관리하게 한다. MCP Apps는 서버가 샌드박스 iframe 안에서 렌더링되는 **rich HTML UI**를 반환할 수 있게 한다.

**쉬운 비유** 음식 배달 앱에 비유하면, 기존 방식은 "주문 완료" 즉답만 줬다면, Tasks Extension은 "지금 조리 중 / 픽업 완료 / 배달 중" 단계를 실시간으로 추적할 수 있는 주문 번호를 주는 것이다. MCP Apps는 그 상태창 자체를 채팅창 안에 작은 앱으로 띄워주는 셈이다.

| 라벨 | 값 |
|---|---|
| 인증 방식 | Anthropic API key (BYOK) 또는 자체 MCP 서버 운영 |
| 비용 | 오픈 스펙(무료) — LLM 호출 비용 별도 |
| 주목할 가치 | `initialize` 핸드셰이크 폐지로 스테이트리스 배포 가능해진 데 이어, 이번 확장으로 장시간 실행 도구(파일 변환, 웹 크롤링 등)를 MCP 안에서 비동기로 처리하는 패턴이 공식화됐다. Cloudflare·Daytona·Modal·Vercel이 샌드박스 파트너로 Day 1 출시 |

**유사 카테고리 비교**

| | MCP Tasks Extension | LangGraph 비동기 노드 | OpenAI Assistants API |
|---|---|---|---|
| 비동기 처리 단위 | MCP tool call | 그래프 노드 | 스레드 + 런 |
| 상태 관리 | 클라이언트가 폴링 또는 콜백 | 프레임워크 내장 | 서버 측 관리 |
| 프로토콜 표준화 | 오픈 스펙(AAIF 관할) | 라이브러리 의존 | OpenAI 독점 |
| 배포 단위 | HTTP 단일 엔드포인트 | Python 프로세스 | OpenAI 호스팅 |

**5분 검증 액션** [obot.ai의 MCP 2026 로드맵 요약 글](https://obot.ai/blog/mcp-is-growing-up-the-2026-roadmap-takes-shape/)에서 "Tasks Extension"과 "MCP Apps" 섹션만 읽으면 두 확장의 핵심 흐름 변화를 5분 안에 파악할 수 있다.

### 2. [macOS notch 코딩 에이전트 모니터 카테고리 (AgentNotch · coucou · Notchcode)](https://feedbagel.com/post/agentnotch-macos-menu-bar-app-for-real-time-ai-coding-assistant-monitoring)

**무엇** 지난 한 주 동안 GitHub 트렌딩에 동시 등장한 세 가지 맥OS용 에이전트 세션 모니터. 공통 기능은 Claude Code·OpenAI Codex 등 여러 코딩 에이전트 세션의 실행 상태(파일 읽기, 툴 실행, 토큰 사용량, 권한 요청)를 화면 notch 또는 메뉴바에서 실시간으로 확인하는 것이다.

| 라벨 | 값 |
|---|---|
| 인증 방식 | 로컬 프로세스 모니터링 — 별도 API key 불필요 |
| 비용 | 세 도구 모두 무료(오픈소스, MIT 라이선스) |
| 주목할 가치 | 한 주 만에 독립적으로 세 개의 유사 도구가 등장했다는 것 자체가 에이전트 병렬 운용에 대한 실무 수요를 반영한다. 세션 데이터가 로컬에만 머무르는 구조로 설계돼 있음 |

### 3. [AgentRun — 에이전트를 감사 가능한 워크플로로](https://zeli.app/story/49821438)

**무엇** 에이전트 실행 흐름을 타입드 DSL로 선언하고, CLI-first 런타임으로 실행하며 런 상태를 레포 로컬에 저장하는 파이썬 라이브러리. Hacker News에서 이번 주 상위권에 올라 에이전트 실무자들의 논의를 이끌었다. 특정 모델에 종속되지 않고 에이전트 흐름 자체를 코드로 버전 관리할 수 있다는 점이 핵심이다.

**쉬운 비유** 요리 레시피(에이전트 흐름)를 손으로 적어두는 대신, 정해진 양식의 카드에 기록해 두면 나중에 어느 요리사(모델)가 보더라도 동일하게 재현하고, 어느 단계에서 어떤 실수가 있었는지도 기록으로 남는 것이다.

| 라벨 | 값 |
|---|---|
| 인증 방식 | BYOK (사용하는 LLM 공급사 API key) |
| 비용 | 무료(오픈소스) — LLM 호출 비용 별도 |
| 주목할 가치 | 에이전트 "흐름"을 코드베이스에 선언형으로 고정하는 접근. 기존 LangGraph가 그래프 실행 엔진을 제공한다면, AgentRun은 에이전트 실행 시퀀스 자체를 타입 안전하게 명세하는 DSL 레이어에 집중 |

**유사 카테고리 비교**

| | AgentRun | LangGraph | AutoGen |
|---|---|---|---|
| 핵심 추상화 | 타입드 DSL 선언 | 그래프 노드·엣지 | 에이전트 간 메시지 |
| 런 상태 저장 | 레포 로컬 | 체크포인터(플러그인) | 메모리 모듈 |
| 진입 장벽 | CLI + DSL 학습 | Python 코드 | Python 코드 |
| 멀티에이전트 | 워크플로 조합 형태 | 네이티브 지원 | 네이티브 지원 |

**5분 검증 액션** [PyPI 페이지](https://pypi.org/user/amirfc/)에서 설치 명령(`pip install agentrun`) 확인 후, HN 스레드에서 개발자가 설명한 기본 DSL 예제 하나를 로컬에서 실행해 run 상태 파일이 레포에 생성되는지 확인.
