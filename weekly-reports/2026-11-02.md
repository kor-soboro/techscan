### 1. [dsh-superagent (DeepSeek Harness Super-Agent)](https://github.com/deepseek-ai/deepseek-harness)

**무엇** DeepSeek Harness 팀이 2026-11-01 공개한 코딩 에이전트 프로토타입. 단일 저장소를 대상으로 GitHub 이벤트를 청취하고 자율적으로 작업을 처리하는 Router-Worker 아키텍처를 채택했다. 동반 설계 문서에 아키텍처 철학도 별도 기재되어 있다.

**쉬운 비유** 콜센터 교환원(Router)이 접수된 요청을 검토해 처리 가능한 건만 직원(Worker)에게 배정하는 구조. 직원은 각자 독립 공간에서 일하고 결과만 원래 대화창에 돌려보낸다.

| 라벨 | 값 |
|---|---|
| 인증 방식 | DeepSeek API key (`DEEPSEEK_API_KEY`) / OpenAI 호환 엔드포인트 BYOK |
| 비용 | 오픈소스 MIT / API 호출 비용 별도 |
| 주목할 가치 | Router-Worker 분리 패턴을 참조 구현 형태로 공개한 최초 사례 중 하나. dsh 하네스의 플러그인 생태계와 결합되어 있어 하네스 아키텍처 학습 자료로도 유효. 단, DeepSeek 공식이 "프로덕션 미준비" 명시 |

**유사 카테고리 비교**

| | dsh-superagent | Microsoft Agent Framework 1.0 | Google ADK v2.x |
|---|---|---|---|
| 라이선스 | MIT | MIT | Apache 2.0 |
| 아키텍처 | Router-Worker 프로토타입 | 선언형 YAML, CodeAct | 이벤트 기반, 멀티에이전트 |
| 성숙도 | 개발자 프리뷰 | 프로덕션 GA | GA (실험적 기능 혼재) |
| 모델 종속성 | 모델 무관 (DeepSeek 기본) | 모델 무관 | 모델 무관 |

**5분 검증 액션** 공식 repo의 `docs/super-agent-design.md` (또는 동반 설계 글)만 읽어서 Router가 어떤 조건으로 Worker를 생성하는지 확인

### 2. [claude-mem — 세션 간 에이전트 영구 기억 플러그인](https://github.com/thedotmack/claude-mem)

**무엇** Claude Code를 포함한 여러 에이전트(Gemini CLI, Codex, OpenCode, Copilot 등)에 세션 종료 후에도 유지되는 기억을 추가하는 오픈소스 MCP 플러그인. 로컬 SQLite + Chroma 벡터 검색으로 이전 도구 사용 기록을 요약·저장하고, 4개의 MCP 도구로 조회한다.

**쉬운 비유** 업무 일지와 같다. 퇴근 전 오늘 한 일을 기록해 두면, 다음날 출근해서 일지를 펼치면 어디까지 했는지 바로 알 수 있다. 에이전트가 새 세션을 시작할 때마다 이 일지를 읽어 이전 맥락을 되살린다.

| 라벨 | 값 |
|---|---|
| 인증 방식 | Claude Agent SDK BYOK (메모리 생성 시 Claude API 호출) |
| 비용 | 오픈소스 Apache 2.0 / 메모리 생성 시 LLM 호출 비용 별도 |
| 주목할 가치 | 단일 설치 명령(`npx claude-mem install`)으로 여러 에이전트에 적용 가능. GitHub 트렌딩 1위 재진입(2026-11-01 기준), 스타 수 기준 해당 카테고리 최다 보유 도구 중 하나 |

**유사 카테고리 비교**

| | claude-mem | mem0 |
|---|---|---|
| 저장소 | 로컬 SQLite + Chroma | 자체 클라우드 또는 셀프 호스팅 |
| 에이전트 지원 | Claude Code, Gemini CLI 등 다수 | SDK 연동 방식 (다수 LLM 지원) |
| 설치 | `npx claude-mem install` | pip / npm SDK |
| 라이선스 | Apache 2.0 | Apache 2.0 (클라우드는 유료 플랜) |

**5분 검증 액션** README의 "How It Works" 섹션을 읽어 3-레이어 워크플로우(캡처→요약→조회) 흐름 파악 후, 자신의 에이전트 스택에 MCP 도구 추가가 가능한지 확인

### 3. [Cursor Agent SDK (GA)](https://www.havoptic.com/r/cursor-agent-sdk)

**무엇** 2026-10-20 정식 출시된 Cursor의 에이전트 정의·배포 SDK. 에이전트를 코드로 작성하고 `npx @cursor/agent-sdk init` 한 줄로 프로젝트를 초기화한 뒤, Cursor 인프라 또는 자체 서버에 배포한다. 보안 리뷰어, PR 자동 수정, Linear/Jira 트리아저 등의 템플릿을 기본 제공한다.

**쉬운 비유** 가전제품 설명서처럼 에이전트의 역할·도구·트리거 조건을 코드 파일 하나로 적어두면, 런타임이 그 설명서를 읽어 에이전트를 알아서 작동시키는 방식이다.

| 라벨 | 값 |
|---|---|
| 인증 방식 | Cursor 계정 (미확인: 독립 API key 여부 별도 확인 필요) |
| 비용 | 미확인 (Cursor 구독에 포함 여부 공식 문서 확인 권장) |
| 주목할 가치 | 에이전트를 코드 에셋으로 관리하는 "Agent-as-Code" 패턴을 IDE 수준에서 공식 지원한 사례. 56%의 PR 병합률 관련 수치가 일부 커버리지에 언급되나 출처 검증 필요 |

**5분 검증 액션** [공식 Cursor 블로그](https://cursor.com/blog) 또는 docs에서 Agent SDK 섹션 확인 후, `npx @cursor/agent-sdk init` 패키지 유효 여부를 npm registry에서 직접 조회 (일부 소스에서 404 보고 있음)
