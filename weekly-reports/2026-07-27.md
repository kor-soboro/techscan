### 1. [MCP 2026-07-28 Specification (Release Candidate → Final)](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)

**무엇** 모델 컨텍스트 프로토콜(MCP)이 2024년 출시 이후 가장 큰 변경을 단행한다. 핵심은 프로토콜 레이어의 완전 stateless 전환이다. `initialize` 핸드셰이크와 `Mcp-Session-Id` 헤더가 사라지고, 각 요청에 클라이언트 정보를 담는 방식으로 바뀐다. 동시에 MCP Apps(서버가 iFrame 인터페이스 제공), Tasks(장기 실행 작업 상태 관리), 공식 Deprecation Policy가 추가된다.

**쉬운 비유** 지금까지는 음식점에 들어갈 때마다 테이블을 배정받고 그 테이블에 고정되어 주문해야 했다. 이제는 번호표 하나로 어느 카운터에서도 주문을 받아준다 — 어느 서버 인스턴스에도 요청이 고르게 분배된다.

| 라벨 | 값 |
|---|---|
| 인증 방식 | 별도 없음 (오픈 프로토콜 스펙) |
| 비용 | 무료 (오픈소스 스펙, SDK 별도) |
| 주목할 가치 | 오늘(7/27) 기준 내일 최종 릴리스. Python v2는 FastMCP → MCPServer 리네임, TypeScript v2는 ESM-only 패키지 분리. 기존 Roots·Sampling·Logging은 Deprecated(12개월 후 제거). 현재 스테이트풀 서버를 운영 중이라면 즉시 마이그레이션 타임라인을 확인해야 한다. |

**유사 카테고리 비교**

| | MCP 2026-07-28 | 이전 MCP (2024-11-05) |
|---|---|---|
| 세션 관리 | 없음 (stateless) | Mcp-Session-Id 필수 |
| 로드밸런서 | 일반 라운드로빈 가능 | 스티키 세션 필요 |
| 확장 기능 | Tasks·MCP Apps 공식화 | 실험적 |
| 하위 호환 | 파괴적 변경 있음(Deprecated 목록 확인 필요) | — |

**5분 검증 액션** [MCP 공식 블로그 글](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)에서 "What's Changing" 섹션을 읽고, [AAIF 마이그레이션 가이드](https://aaif.io/blog/mcp-2026-07-28-whats-changing-and-how-to-migrate)에서 기존 서버에 영향받는 항목을 확인한다.

### 2. [OfficeCLI](https://github.com/iOfficeAI/OfficeCLI)

**무엇** AI 에이전트가 Word(.docx)·Excel(.xlsx)·PowerPoint(.pptx) 파일을 읽고 편집하고 자동화할 수 있도록 만들어진 CLI 도구다. Microsoft Office 설치 없이 동작하는 단일 바이너리로 macOS·Linux·Windows를 지원한다. 내장 HTML 렌더링 엔진이 문서를 HTML 또는 PNG로 변환해 에이전트가 결과를 시각적으로 확인하는 루프까지 지원한다.

**쉬운 비유** 지금까지 AI 에이전트가 Office 파일을 다루려면 Office가 설치된 컴퓨터에서만 가능했다. OfficeCLI는 Office 없이도 어디서나 AI가 서류 가방을 열고 문서를 수정할 수 있게 해주는 범용 열쇠 묶음이다.

| 라벨 | 값 |
|---|---|
| 인증 방식 | 없음 (도구 자체는 인증 불필요, 에이전트의 LLM 키는 별도 설정) |
| 비용 | 무료(MIT 오픈소스) |
| 주목할 가치 | GitHub 트렌딩 최상위권, 10,800+ 스타. Docker·CI 파이프라인·헤드리스 서버 환경에서도 디스플레이 없이 동작. Claude Code, Cursor, Windsurf, GitHub Copilot 등 에이전트와 즉시 연동 가능. |

**유사 카테고리 비교**

| | OfficeCLI | python-docx / openpyxl | Pandoc |
|---|---|---|---|
| 지원 포맷 | docx·xlsx·pptx | docx 또는 xlsx (각각 별도) | 다양한 문서 포맷 |
| 에이전트 CLI 네이티브 | ✓ | ✗ (라이브러리) | 부분 지원 |
| 렌더링(HTML/PNG) | ✓ | ✗ | ✗ |
| 설치 | 단일 바이너리 | pip 패키지 | 단일 바이너리 |

**5분 검증 액션** [GitHub README](https://github.com/iOfficeAI/OfficeCLI)의 "Quick Start" 섹션에서 바이너리 1개 다운로드 후 `officecli read sample.docx` 한 줄로 동작 확인.

### 3. [OpenWiki (LangChain)](https://github.com/langchain-ai/openwiki)

**무엇** LangChain 팀이 만든 CLI로, 코드베이스를 분석해 AI 에이전트가 소비하기 좋은 형태의 위키 문서를 자동 생성하고 유지한다. Andrej Karpathy가 제안한 'LLM Wiki' 개념(RAG 대신 리빙 위키를 유지)을 실용적으로 구현했다. Mermaid 다이어그램(시퀀스·ER·상태 다이어그램)을 자동 삽입하고, GitHub Action으로 코드 변경 시 문서를 자동으로 PR 제출한다.

**쉬운 비유** 도서관 사서가 새 책이 들어올 때마다 색인 카드를 스스로 업데이트하듯이, OpenWiki는 코드가 바뀔 때마다 AI가 읽기 좋은 안내 책자를 알아서 고쳐준다.

| 라벨 | 값 |
|---|---|
| 인증 방식 | Anthropic API key (BYOK) / OpenAI API key (BYOK) / OpenRouter 등 다중 프로바이더 BYOK |
| 비용 | 무료(오픈소스), LLM 호출 비용 별도 |
| 주목할 가치 | CLAUDE.md·AGENTS.md 파일에 자동으로 위키 참조 지시문을 추가해 코딩 에이전트의 컨텍스트 검색 효율을 높인다. OpenWiki Brains로 Gmail·Notion·Jira·Slack 등 외부 데이터 소스도 위키에 통합 가능. |

**유사 카테고리 비교**

| | OpenWiki | Mintlify | Swimm |
|---|---|---|---|
| AI 에이전트 최적화 | ✓ (AGENTS.md/CLAUDE.md 직접 연동) | ✗ (개발자 문서 사이트) | ✗ (코드 연동 문서) |
| 자동 업데이트 | ✓ (GitHub Action) | 수동 또는 제한적 | 수동 |
| 다이어그램 자동 생성 | ✓ (Mermaid) | ✗ | ✗ |
| 외부 소스 통합 | ✓ (Brains 기능) | ✗ | ✗ |

**5분 검증 액션** `npm install -g openwiki` → `openwiki --init` → 작은 사이드 프로젝트 폴더에서 첫 위키 생성 결과를 확인한다.

## ⚠️ ToS 제약 가능 카테고리

해당 카테고리는 일부 플랫폼의 third-party OAuth 정책에 따라 사용에 제약이 있을 수 있어 별도로 분류합니다. 도구 사용 전 자신의 상황·계약·정책에 맞는지 확인 필요.

- **[OmniRoute](https://github.com/diegosouzapw/OmniRoute)** — MIT 라이선스 자체 호스팅 AI 게이트웨이로, 단일 엔드포인트에서 290+ LLM 프로바이더(90+ 무료 티어)를 연결하고 Claude Code·Cursor·Codex 등에서 사용 가능하다. BYOK 방식(각 프로바이더의 공식 API 키)으로 사용하는 것이 기본 시나리오이나, 일부 사용자가 Claude.ai 구독 OAuth 토큰을 우회 연결하는 방식을 시도하고 있다. Anthropic은 최근 서드파티 도구의 OAuth 접근을 공식 지원 범위 밖으로 명시하고 관련 법적 공지를 발송한 사례가 있다. 도구 자체는 오픈소스이나 Claude.ai OAuth 토큰 경유 설정은 Anthropic ToS 위반에 해당할 수 있어, 사용 전 각자의 계약·약관 확인이 필요하다.
